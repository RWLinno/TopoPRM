## 诊断报告：为什么 TopoPRM full 在 GSM8K/MATH500/CNMO/MMLU 没赢过 outcome-only

### 核心 Bug #1（最致命）：`TopoSCAEReward.__call__` 把 outcome 信号完全抹掉了

[`src/reward/composite_reward.py:730-748`](src/reward/composite_reward.py)

```python
def __call__(self, completions, ...):
    base_rewards = [self._sanitize(v) for v in self._base(completions, ...)]   # ← TopoCompositeReward 输出
    outcome_scores = [self._clip01(self._sanitize(v)) for v in self._outcome(...)]
    
    pos_idx = [i for i, o in enumerate(outcome_scores) if o >= 0.66]
    neg_idx = [i for i, o in enumerate(outcome_scores) if o < 0.66]
    
    pos_norm = self._normalize(pos_vals)   # 仅做 (R_i - mu) / sigma，纯方差归一化
    neg_norm = self._normalize(neg_vals)
    
    shaped = [0.0] * len(base_rewards)
    for k, i in enumerate(pos_idx):
        shaped[i] = clip(pos_norm[k], 0, 1.5)     # ← B+ 归一化后的值，可能只有 0.3
    for k, i in enumerate(neg_idx):
        shaped[i] = clip(neg_norm[k], -1.5, 0)    # ← B- 归一化后的值，可能只有 -0.5
    return shaped
```

**致命问题**：归一化后，B+ 里"答对的最差那一条" `shaped ≈ 0.0`，B- 里"答错的最好那一条" `shaped ≈ 0.0`。再加上 GRPO 的 group-wise advantage 又会做一遍归一化，**outcome 信号的强度被人为压扁到和 topology 噪声同一量级**。

正确的 PASC-GRPO SCAE 公式应该是：
```
A_i = clip( (R_i - mu_pm) / (sigma_pm + eps), [0, c] if i in B+, [-c, 0] if i in B- )
```
PASC 论文里关键是**保留量纲**：B+ 的所有 sample 都有正 advantage，B- 的所有 sample 都有负 advantage，**outcome 是绝对优先序**。当前实现把它退化成"B+ 内部 / B- 内部排序"，跨 stratum 的优先序丢了——也就是说：

> 一个**结构垃圾但答对**的 trace（B+ 里最差的，shaped=0.0）== 一个**结构完美但答错**的 trace（B- 里最好的，shaped=0.0）

→ 这就是 GSM8K/MATH500（outcome 容易满足）上 TopoPRM 反而**输给** outcome-only GRPO 的根因：outcome 信号被 SCAE 错误归一化抹平了。

更糟的是 line 696-698 的注释承认：
> "ms-swift does not expose GRPO internal advantage computation in this repository. This class implements stratified clipping at reward-output level **as a practical drop-in approximation** for correctness-first reward shaping."

这是个 reward-level 的近似实现，**不等价于** advantage-level 的 SCAE。

### 核心 Bug #2：分层奖励聚合是**加法**不是**乘法**

[`src/reward/composite_reward.py:478-485`](src/reward/composite_reward.py)

```python
for o, f, t, c, l in zip(outcome_scores, format_scores, topo_scaled, cont_scaled, length_scores):
    r_base = bw["outcome"] * o + bw["format"] * f + bw["length"] * l    # ← 加法
    r_base_floored = max(r_base, floor)                                  # ← BASE_FLOOR=0.05
    gain = 1.0 + alpha * t + (1.0 - alpha) * c
    r = r_base_floored * gain
```

论文写的是：
```
r_total = r_outcome * (1 + alpha*q_topo + (1-alpha)*q_cont) * r_format * r_length
```

**实际代码做的是**：
```
r_total = max(0.6*r_out + 0.2*r_fmt + 0.2*r_len, 0.05) * (1 + alpha*q_topo + (1-alpha)*q_cont)
```

后果三连击：

1. **Outcome 不再是"乘法门"**：r_out=0 不会让整体奖励变 0，因为 `r_format=1.0` 几乎总是成立（格式不是难事），所以 `r_base ≈ 0.2`，再乘以高 q_topo 仍然能拿到不错的奖励。这正是论文方法论核心要避免的事。

2. **`BASE_FLOOR=0.05` 是 BUG FIX 反而加重了 BUG**：line 82-85 注释明说：
   > "Floor on the multiplicative base term so that topology gain is never zero-ed out when r_base = 0 (outcome=format=length=0). This is a BUG FIX..."
   
   这"修复"的代价是：r_out=0 时 reward 不再为 0，topology 奖励变成"答错也能加分"的纯拓扑 hacking 通道。

### 核心 Bug #3：Continuity reward 退化为常数
